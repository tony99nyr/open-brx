How it's wired

Three tiers of hardware that never all talk at once, and why.

benchsoftwarespecLast verified 2026-08-27How we knowMarkdown

Read this before you trust any diagram.

Open BRX is not one program. Four hard facts shape every awkward part of the design. Stock firmware is never modified. The gun cannot report its own kills. Native feel and host control cannot both happen unless a live host drives the feel. And the field is offline and spread out.

Tier 0 is real today. Tier 1 is what buys you a field, and it has never been run on one.

A full Team Deathmatch ran end to end on two real taggers on 2026-08-25. That run had scoring, respawn, a frag limit, the correct winner, and BLE holding the whole match. A three-gun synced start is hardware-proven too. The phone-node path has one proof only: one phone → Mission Control → one gun at the bench (2026-08-25 night). A match with several phones over real field Wi-Fi has not been run. Neither has a dispersed timed start, or a store-and-forward recovery after real coverage loss. bench/software

Which links are up, phase by phase

(PLAT-08)

  1. Armory: USB to each gun, one time, at home. bench
  2. Muster: node↔gun BLE up, node↔MC Wi-Fi up, readiness board (gun battery, firmware, headset, phone battery, clock sync). software
  3. Build: the host writes the game. No guns involved. software
  4. Kit: assign player number, name, team, weapon and voice. A weapon try-out pushes real frames so the player can feel it. bench (try-out fired a real gun from MC, 2026-08-25)
  5. Lobby: players ready up. MC pushes the per-player FrameBundle. Each node writes it to its gun and acks with the gun's echo. software
  6. Dispersed start: MC sets a go-live wall-clock time. Players walk out of range. Each node counts down on its own, so no signal is needed at T-0. software
  7. Live play: node↔gun BLE up, node↔MC Wi-Fi best-effort, MC↔gun BLE: never. software
  8. Recap: players return, nodes flush, MC works out winner, K/D, accuracy and medals. CSV export. software

Source: docs/architecture-topology.md §4, docs/spec/README.md §3, mcp/brx_mcp/mc/API.md

Source: docs/architecture-topology.md §5, docs/spec/README.md §3 "Coverage honesty"

So on a large field: you always know you died. You may not learn you got a kill until you walk back into range.

Final results are never wrong, only late. Kills live in the victims' reports, so a scoreboard stays provisional until every node has flushed. Put respawn and base points inside Wi-Fi coverage, so every death becomes a sync point. Instant field-wide feedback is the Companion mesh (M6). software/spec

What happens when things break

Failure What happens Status
Field Wi-Fi drops Nodes keep playing; events queue locally and flush on return software
BLE drops mid-match The node re-probes on reconnect; the gun's config survives a BLE drop bench bench
Gun is power-cycled Config is wiped; a zeroed $LCD echo is the node's tell to re-push bench bench
Phone dies That player is out. One phone = one gun = one node, with no backup design
Node never returns Recap stays provisional; that player's kills are missing design
Headset off or asleep The gun quietly refuses to join. A disconnected headset slow-blinks rainbow, which is a free visual muster check bench 2026-08-25 / 27
