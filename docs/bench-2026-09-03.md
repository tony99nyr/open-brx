## ⚠️ PRE-FLIGHT — do these three in order, every time

**1. Kill stale `brx_mcp` processes.** A forgotten server from a previous session HOLDS a gun: the
tagger is invisible to `scan`, announces "phone connected" with no phone in the room, and can be
armed or spawned underneath you.

```powershell
Get-CimInstance Win32_Process -Filter "Name like '%python%'" |
  Where-Object { $_.CommandLine -like '*brx_mcp*' } | Select-Object ProcessId, CreationDate
```

⚠️ `list_connections` is NOT sufficient — it reported `connected: false` while a *different* process
held the gun. Enumerate at the OS level. (`gotchas.md`)

**2. Check the emitter actually reaches.** 🔴 **This is the session's blocker — see below.** Fire six
witnessed shots at the headset at the distance you intend to work at:

```
# ⚠️ WSL's python has NO Bluetooth and no COM ports. Always the Windows venv:
PY=/mnt/c/Users/Tony/.brx-mcp/venv/Scripts/python.exe
cd mcp/tools && $PY range_step.py <addr> "range check" COM8 6 COM7
```
(On the MacBook there is no Windows venv and no COM port: use the native `python3` and the Mac's
own serial device paths.)

**2b. Check the RIG before trusting any IR number.** `$PY loopback.py COM8 COM7 12` — PING both
boards, then compare what the receiver decodes against what was sent. ⚠️ Expect it to look bad: the
receiver fragments frames (**F12**), so use it to confirm the boards are ALIVE, not as a decode
benchmark.

**2c. Four traps that each cost hours — read `gotchas.md` if you have not this week.**
`$HIR` never reaches BLE in a gun's own native game · env vars do NOT cross the WSL→Windows boundary
(a tuning flag silently did nothing and the result was believed) · a lit LED washes its neighbours so
luminance cannot tell lit from dark · **never end a run on a bare `$CLEAR`** (it wipes the `$SIR`
table and the gun then ignores every hit while reporting healthy).

**3. Never conclude "deaf" without reading pools.** A DEAD gun and a `$SIR`-less gun are
indistinguishable through `$HIR`. Tony: *"it isn't going to register a hit while dead. thats dead not
deaf."* The tools now check this themselves; a hand-run probe must too.

## ~~🟡 4. F12 — the receiver fragments frames (blocks the grenade)~~ (WORKED AROUND, see above)

Our emitter decoded whole only 4/20, a **real BRX gun** only 3/44, with every frame arriving as a
full 52 edges. The board mis-assembles what arrives. **Long accessory words are its worst case, so
grenade capture is blocked** — anything captured today would be fragments recorded as facts.

Cheapest first: move the receiver back / off-axis and re-run `loopback.py`. If the clean-decode rate
climbs with distance it is VS1838B saturation and the answer is an attenuator, not a code change.

## Method rules this bench has earned

1. **A difference is real only if both sides were measured in the same burst.** (2026-09-02 morning)
2. **On an intermittent fault, nothing is a cause until it reproduces on demand.** Six confident
   explanations died to controls in one evening, every one from a single run.
3. **Look at the hardware before trusting the metric.** Three times in one night — the LED wash, the
   segment measurement, the strobe — cropping the image or asking the operator resolved in seconds
   what the instrument got wrong. The strobe was invisible to the metric *by construction*.
4. **Read the pools before saying "deaf".**
